Como a corretora funciona hoje

O usuário se autentica no Supabase, chama uma Edge Function em TypeScript e a operação é registrada no Postgres. As classes de POO organizam os dados e o fluxo.

01 / VISÃO GERAL

Cinco passos, uma requisição

A seta mostra por onde o pedido passa. Cada caixa tem uma responsabilidade; nenhuma precisa fazer o trabalho de todas as outras.

01

Usuário + Auth

O Supabase Auth identifica quem está fazendo a chamada e fornece o token de sessão.

02

Edge Function

Recebe a rota, exige autenticação, lê os dados e devolve JSON com o resultado ou erro.

03

Corretora

O serviço valida a operação e coordena os objetos e o acesso aos dados.

04

Repositório

Converte a ação em consulta Supabase ou chamada RPC e monta a resposta.

05

Postgres

Guarda as tabelas, limita a leitura por usuário e aplica operações transacionais.

A resposta volta pelo caminho inverso até o frontend. A tela básica de cadastro e consulta já está no repositório.

    Onde a POO aparece

    A Edge Function é a entrada HTTP. As classes dão nomes e responsabilidades aos conceitos do sistema.

    Dinheiro e QuantidadeValidam texto decimal e usam inteiros para evitar perda de precisão.
    Conta, Ativo e PosiçãoRepresentam a carteira e transformam dados do banco em uma resposta clara.
    CorretoraCoordena cada caso de uso e depende da interface RepositorioCorretora.
    RepositorioSupabaseImplementa a interface e sabe consultar tabelas e chamar funções SQL.

    A regra crítica também existe no banco: compra e venda verificam saldo ou quantidade e gravam tudo na mesma transação. Isso mantém os dados consistentes mesmo com chamadas simultâneas.

    03 / BANCO DE DADOS

    O que fica salvo

    O Supabase Auth guarda o login. As quatro tabelas da corretora guardam o saldo, os ativos e o histórico.

    auth.users

    Usuário e autenticação, gerenciados pelo Supabase.

    id → contas.usuario_id

    contas

    Uma conta por usuário, com saldo em centavos.

    id · usuario_id · saldo_centavos

    posicoes

    Quanto a conta possui de cada ativo.

    conta_id · ativo_codigo · quantidade_micros

    movimentacoes

    Registro de depósito, compra e venda.

    conta_id · tipo · valor_centavos

    ativos é o catálogo compartilhado: código, nome, tipo e preço fictício. RLS limita a leitura de contas, posições e movimentações ao usuário dono da conta.

    O cadastro cria a conta automaticamente por um trigger em auth.users. A Edge Function chama depositar, comprar e vender por RPC. A função abrir_conta continua disponível para recuperar usuários antigos sem conta.
